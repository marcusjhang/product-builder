## Unreleased

Two more field runs (2026-09-18 and 2026-09-19, a private repo, the suite read from files rather than installed), one that planned an opt-in AI reranker for a search box through the Bounded path and one that planned and shipped two stacked model-routing features. What held: the sizing table and the Bounded caps, premises at G1, the tech-lead panel (five structural defects the author had missed in one run, a sentinel that collided with an existing name killed before code in the other), dismissal with the user's decision named, the ledger, the printed Definition of Ready. What fought: a one-page cap that contradicted the templates, frame questions re-asking what the chat had settled, a success signal whose halves were counted at different grains, a panel that reviewed a moving tree, a reviewer prompt that anchored to the draft instead of the baseline, an Evidence contract that assumed a PR asset upload `gh` does not have, a setup that skipped the two environment facts that later cost an hour, a plan that drifted from its own rulings until a reviewer noticed, a change-site census that named one path where there were two, a synchronous external call on a launch hot path that no template asked about, a behavioural clause locked without a detection mechanism, and a rollout gate that stayed implicit. The changes: the Bounded row caps `product.md` at two pages and `implementation.md` at three in a Bounded template variant that templates.md now defines; decisions the user stated before the suite ran are D-rows at intake and are never re-asked, and an artifact the same session produced is folded into the plan or deleted before Ready; the success-signal question names the event, numerator, denominator, and grain; every behavioural clause in a decision names its detection mechanism and cost before it locks; the plan's verify step reconciles both docs against the rulings table and the Definition of Ready has a box for it; research's map and the changes table carry a change-site census; `implementation.md` gains an External calls section (sync or async, timeout, latency budget, failure mode, the key that pays) and the Definition of Ready requires it; the Rollout line gains a live gate and ship's pre-flight checks it; techlead casts the tech lead plus at most one seat on Bounded, freezes the tree while seats run, and tells seats to anchor to the baseline when a draft exists; research allows zero explorers when the session already read the area and records a blocked spike with an owner; verify validates an unvalidated `drive.md` on first run, refuses to follow a login proxy, and treats a dead credential as a friction event with one batched question; setup probes the database and cache, reads the provisioning script for rewritten env values, points at `profiles/default.md` as the schema, and asks once whether to commit `.product-builder/`; the Evidence default is screenshots committed under the plan folder within a size cap and recordings linked; implement supports one PR with ordered commits as a named shape; an agent-owned ledger row may be edited in place with a dated note; the review's QA seat treats a test that cannot fail as a finding; the mode says when it is running from files, batches remaining blockers into one question once the user has delegated the run, and states that a step naming a cast is the subagent request the harness needs.

Built first, nine fixes from a field run, and nine more playbooks. From a session on a private repo (2026-09-19) where the suite was not installed and a feature was built, reviewed in three rounds, and opened as one large PR without it: a display gap that an interview question would have surfaced before a line was written, three product calls resolved silently as execution calls, no appetite check, each round of fixes producing the next round's regressions, a failure in an untouched test that a changed-files run could not see, a metered request measured only because reviewers chose to, prompt text that no seat read as the model would, and a forge with two logins that every push had to work around. Intake validates the premise against the system before it asks. A judge. The profile may name a decision model (`Judge` section: `Model: typesafe/jev-latest | none`, `Mode: shadow | gate`) that six gates consult through `skills/product-builder/scripts/judge`, with every question and threshold in `skills/product-builder/references/judge-questions.json`: `question-gate` runs as a `PreToolUse` hook on the question tool (`hooks/hooks.json`) and, in `gate` mode, blocks a question an experiment or a read would settle; `anchor` checks a file:line claim against its excerpt (how, research); `spec-line` checks an acceptance line against the test that claims it (review `--contract`); `finding` and `finding-pair` bucket panel and review findings with a calibrated confidence (pm, techlead, review, personas); `pr-comment` triages review comments (babysit). `shadow` mode logs verdicts to `.product-builder/judge-log.jsonl` and changes nothing; setup writes `shadow`, reflect reads the log and proposes `gate`. No key or `Model: none` keeps every gate on the session model, said once per run. Not yet run against the live API.
